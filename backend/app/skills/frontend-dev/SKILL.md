# Frontend Development & UI Design Skill (Claude Code Style)

このスキルがアクティブになった場合、以下のプロフェッショナルなUI開発・ベストプラクティスを厳格に遵守してください。

## 1. デザインと視覚的エクセレンス（Rich Aesthetics）
- **モダンで美しいUI**: ユーザーが一目で感動するようなリッチなUI（適切なカラーパレット、ダークモード対応、グラスモーフィズム、ホバーアニメーションやマイクロインタラクション）を提供すること。
- **プレースホルダー画像や不確かなリンクの禁止**: UIを作る際、画像が必要な場合は適切なデモ用ダミー画像かSVGアイコン（Lucideアイコン等）を用い、壊れたリンクが発生しないよう実装すること。

## 2. React & TypeScript ベストプラクティス
- **安全なコンポーネント設計**: `Cannot read properties of undefined` のようなランタイムエラーを防ぐため、配列マッピング時は `Array.isArray(list) ? list.map(...) : []` やオプショナルチェーン (`?.`) を徹底的に活用すること。
- **クリーンなJSX**: マークダウン描画や外部コンポーネントのラップ時は、閉じタグ漏れやプロパティ（`components` 等）の渡し忘れがないよう、厳密な型チェックと構文チェックを行うこと。

## 3. 検証とテスト
- フロントエンドファイルの作成・修正（`<file path="...">` 等）を行った後は、可能であれば必ず TypeScript コンパイルチェック (`npx tsc --noEmit`) をバックグラウンドで走らせ、エラーゼロを確認してからユーザーに報告すること。

## 4. 【絶対厳守】トークン切れ根絶とボイラープレートの最適化
- **ボイラープレート自作によるトークン浪費の禁止**: 新規React/Viteプロジェクトを作成する際、`package.json`, `tsconfig.json`, `vite.config.ts`, `vite-env.d.ts` 等の定型的な設定ファイルをAIが1個ずつ手作りのテキストで出力してトークンをドカ食いすることは厳禁です！これらは必ずターミナルコマンド（`npx -y create-vite@latest ...` 等）で一括自動生成させるか、最小限の構成にし、**AIの貴重な出力トークンは全て本丸のUIコンポーネントコード（`App.tsx` やスタイリング）に100%集中**させてください。
- **冗長なおしゃべりと細切れ出力の禁止**: 「おっしゃ！次は○○を作るで！」等の長い前置き・後置きトークや、小さなファイルを何度も細かく分けて出力する行為を禁止します。1回のレスポンスで確実に本丸のUIを完成させる高密度かつ無駄のない出力を行い、トークン上限によるレスポンス切れ（「つづき」と言わせる事態）を徹底排除すること。
